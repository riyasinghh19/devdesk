Cron Explainer

Type a cron expression and see what it means in plain English, plus exactly when it will run next. Works for crontab, GitHub Actions, Airflow, Kubernetes CronJobs and most schedulers.

Try

    How to read a cron expression

    A standard cron expression has five fields separated by spaces. Each field says when the job may run, and the job runs when all of them match.

    ┌───────── minute (0–59)
│ ┌─────── hour (0–23)
│ │ ┌───── day of month (1–31)
│ │ │ ┌─── month (1–12 or JAN–DEC)
│ │ │ │ ┌─ day of week (0–6 or SUN–SAT, 7 is also Sunday)
│ │ │ │ │
0 9 * * 1-5   →  at 09:00, Monday to Friday

    Special characters

    SymbolMeaningExample
    *Every value* * * * * runs every minute
    ,A list of values0 9,18 * * * runs at 09:00 and 18:00
    -A range0 9 * * 1-5 runs on weekdays
    /A step*/15 * * * * runs every 15 minutes
    @dailyShortcut for 0 0 * * *Also @hourly, @weekly, @monthly, @yearly

    Gotchas that catch everyone

    • Time zones. Cron runs in the server's time zone. GitHub Actions and most cloud schedulers use UTC, so 9 AM IST is 30 3 * * *.
    • Day of month OR day of week. If you set both, the job runs when either matches. 0 0 13 * 5 runs on every 13th and every Friday, not only on Friday the 13th.
    • Steps start from the range. */10 in the minute field means 0, 10, 20…, not "10 minutes after the job starts".
    • Six fields? Quartz and Spring add a seconds field at the start, and AWS EventBridge adds a year at the end. This tool reads the standard five fields; drop the extra one to check your schedule.

    Frequently asked questions

    How do I run a job every 5 minutes?

    Use */5 * * * *. For every 5 minutes during office hours on weekdays, use */5 9-17 * * 1-5.

    How do I schedule 9 AM IST in GitHub Actions?

    GitHub Actions uses UTC, and IST is UTC+5:30, so 9:00 IST is 3:30 UTC: 30 3 * * *. Pick UTC in the time zone menu above to check.

    How do I run on the last day of the month?

    Standard cron has no "last day" symbol. A common trick is to run on days 28–31 and check the date in your script, for example [ "$(date -d tomorrow +%d)" = "01" ] && ./job.sh. Quartz supports L for this.

    Is anything I type sent anywhere?

    No. The explanation and run times are calculated in your browser.
